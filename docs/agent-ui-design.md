# 智能体三页 UI / 交互设计方案

> 评审稿 · 2026-11-28 · 对应页面：`views/system/agentApp/index.vue`、`views/system/agentControl/index.vue`、`views/system/remote/index.vue`
> 配套可点击原型：`docs/agent-ui-prototype.html`（直接用浏览器打开）

## 一、先说结论

现状三页共用同一套「选项目/应用 → 一大段只读提示词 → 复制/下载 → 页尾黄色警告」的结构。它把**配置后台做成了文本生成器**：用户真正要做的是「让智能体成功接入并安全地干一件事」，提示词只是中间产物。

三个核心改动：

1. **按任务而不是按技术命名**：顶层「智能体应用」→「智能体」；子项改为「应用生成 / 设备控制 / 远程运维」，各带一句副标题说明用途与风险等级。
2. **把提示词降级为向导最后一步**：统一四步流程 `选择上下文 → 配置权限/需求 → 获取接入包 → 验证与收尾`，提示词放在第 3 步，前面先让用户确认自己选对了项目和权限。
3. **凭证默认遮蔽 + 风险提示前置**：AppID/Secret、运维令牌不再明文躺在 textarea 里；高风险提示放在凭证旁边（用完即走），页尾大段警告删掉或收进右侧帮助栏。

## 二、现状问题清单（按严重程度）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| P0-1 | Secret / token 明文展示在 10 行 textarea，风险警告却在页面最底部 | 三页 `prompt` computed + 页尾 `el-alert` | 用户复制前看不到警告；截图/共享屏幕直接泄露 |
| P0-2 | 远程运维令牌等同「节点任意代码执行」，展示方式与只读密钥无区别，无遮蔽、无剩余时间感知 | `remote/index.vue` | 高危凭证被当作普通文本对待 |
| P0-3 | 默认自动选中第一个项目/应用（`loadApps` 里 `this.appId = this.appOptions[0].id`） | agentApp / agentControl | 用户没确认就把错误项目的 Secret 复制给智能体 |
| P0-4 | 复制只有 `navigator.clipboard`，失败仅提示手动复制，无 fallback | 三页 `copyText` | HTTP 环境/嵌入 iframe 时功能直接失效 |
| P1-1 | 三页视觉与文案高度同构，但用途和风险完全不同，用户分不清该进哪一页 | 菜单 + 三页 | 认知负担、误用（尤其控制与运维） |
| P1-2 | 没有「接入是否成功」的反馈与状态：是否已下载、是否已复制、智能体是否连上，一概不知 | 三页 | 用户离开页面后无法判断下一步 |
| P1-3 | 项目被 URL 上下文锁定时，下拉框只是 disabled，没有解释 | `projectLocked` | 用户以为是 bug |
| P1-4 | 固定 760px 单卡 + 页尾警告，右侧大片留白；提示词 textarea 不像代码/凭证展示区 | 三页样式 | 工具页观感，缺乏可信任感 |
| P2-1 | 应用列表只显示 name，看不到 appid 尾号、启用状态 | 两页 `el-option` | 选错难发现 |
| P2-2 | 「下载 SKILL」在未选应用时仍出现在提示文案里，和「请选择应用」并列 | agentApp / agentControl else 分支 | 流程入口分散 |
| P2-3 | 三个页面约 80% 代码重复 | 三页 | 一致性靠人肉维护，改一处漏两处 |

## 三、信息架构与命名

**推荐方案（动词导向，任务清晰）：**

```
智能体                       ← 原「智能体应用」，去掉歧义
├─ 应用生成   /agent/app     ← 原「智能应用」：生成 Python + MySQL 物联网应用
├─ 设备控制   /agent/control ← 原「智能控制」：查询/控制平台设备
└─ 远程运维   /agent/remote  ← 原「智能运维」：erl-cli 后端调试通道
```

每页标题下固定一句副标题 + 风险徽标：

| 页面 | 副标题 | 风险等级 |
|---|---|---|
| 应用生成 | 按平台设备数据，让智能体生成一个独立应用 | 中（含 AppID/Secret） |
| 设备控制 | 让智能体以应用身份查询或控制设备 | 高（可下发控制指令） |
| 远程运维 | 临时开放后端节点调试通道，排查完立即关闭 | 极高（等同任意代码执行） |

> 若不想动菜单 URL/权限，可只改 `menu_name` 与页面副标题，不改 `path` 和 `perms`，迁移成本最低。

## 四、统一交互框架

三页共用同一套页面骨架（建议抽成 `AgentAccessLayout` + `AgentAccessWizard`）：

```
┌─ 页面头：标题 / 副标题 / 风险徽标 ─────────────────────────┐
│ [步骤条] 1 选择上下文 → 2 配置权限 → 3 获取接入包 → 4 验证与收尾 │
│ ┌─ 主区（任务） ──────────────┐ ┌─ 右侧栏（安全/帮助） ──┐ │
│ │ 当前步骤表单 / 凭证 / 提示词  │ │ 风险须知（就近提醒）     │ │
│ │ [上一步] [下一步/完成]       │ │ 常见问题 / 应急入口      │ │
│ └────────────────────────────┘ └───────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

**四步的含义：**

1. **选择上下文**：项目 + 应用（运维页是平台级，改为「确认 range/有效期」）。默认**不预选**，必须用户主动确认；锁定项目显示锁形图标 + tooltip「由当前项目上下文决定」。
2. **配置权限**：生成页填需求摘要；控制页选只读/可控制；运维页选有效期。此步决定第 3 步生成的提示词内容，让用户先看懂再复制。
3. **获取接入包**：下载 SKILL → 查看凭证（默认遮蔽，`显示` / `复制` 分离）→ 查看提示词代码块 → 复制。**提示词预览里的凭证同样遮蔽**，只在点击「复制完整提示词」时把完整值写入剪贴板；顶部标注「预览已遮蔽 · 复制时自动填入完整凭证」。
4. **验证与收尾**：本地清单（已下载 / 已复制 / 智能体已确认）+ 页面专属动作（试连 / 查看连接记录 / 停止通道）。清单存 localStorage，只做辅助，不作为安全依据。

**通用组件建议：**

- `AgentPageHeader`：标题、副标题、风险 badge
- `AgentStepper`：四步状态、可回退不可跨越（未填完不允许下一步）
- `CredentialField`：AppID 明文 + Secret 遮蔽/显示/复制，支持泄露应急链接
- `PromptBlock`：代码块样式（等宽字体、行号可选、折叠）、变量说明 chips、复制按钮、敏感标记
- `RiskAside`：按页面风险等级配置文案与操作入口，sticky 定位
- `AgentAccessWizard`：把上述组件按场景配置组装，三页只剩配置对象差异

## 五、三页详细设计

### 5.1 应用生成

- 第 1 步：项目/应用两个选择器；下方「当前接入：项目 × / 应用 ×」摘要条，切换应用时摘要即时更新。空状态给「去应用接入创建」跳转按钮，而不是只写一句话。
- 第 2 步（新增）：需求摘要 —— 应用名称、场景模板（设备数据同步 / 告警分析 / 数据看板）、设备规模、数据库位置、补充说明。这些字段进入提示词，避免用户对着空白文本框现编需求。
- 第 3 步：`alinkiot-app.zip` 下载卡 + `uzyiot-api.zip` 依赖说明 + 凭证区 + 提示词预览。提示词顶部用 chips 标出「项目 / appId / Secret / host」四个变量来源。
- 第 4 步：接入清单 + 「智能体会先问你设备规模」的预期管理文案。

### 5.2 设备控制

- 第 1 步：同应用生成，但应用选项补 `appid****` 尾号和启用状态。
- 第 2 步（新增）：**权限范围**单选 —— 只读查询 / 查询 + 设备控制；「控制指令需我确认」开关默认开；显示本次可访问的数据范围（当前项目、设备数）。提示词随权限范围即时变化，用户能看到「选了只读，提示词里就不会出现控制指令」。
- 第 3 步：`uzyiot-api.zip` 下载 + `env.ini` 配置说明 + 凭证区 + 提示词预览。
- 第 4 步：接入清单 + 「试连」按钮（后端如无接口，可先做前端模拟并标注 Demo）。试连结果展示「智能体已确认项目与设备范围」。
- 右侧栏强调：控制指令的影响范围、误操作恢复方式、Secret 轮换入口。

### 5.3 远程运维

- 第 1 步：启动卡 —— 说明这是临时通道，选有效期（1–168h，默认 24h）后点「启动通道」；启动前展示风险确认（勾选「我确认仅在排查时开启」）。
- 第 2 步：状态仪表 —— 大号状态点 + 剩余时间倒计时 + 进度条；令牌默认遮蔽 `••••••••••••9f3c`，操作为「显示 / 复制 / 重新生成 / 立即停止」。「重新生成」和「停止」用不同级别的确认文案：
  - 重新生成：「旧令牌立即失效，正在使用的智能体会断开。确认重新生成？」
  - 停止：「停止后令牌立即失效，已建立的连接最长 5 分钟内断开，正在执行的调试会中断。确认停止？」
- 第 3 步：`erl-cli.zip` 下载 + 连接参数卡（host / port / token）+ 提示词预览 + 清单。
- 第 4 步：连接记录表（时间 / 来源 IP / 命令数 / 结果），有接口就接后端，没有就先展示空状态「暂无连接记录」。停止按钮始终可见（红色，放在状态卡右上），不要藏进弹窗。
- 右侧栏风险提示前置且常驻：「此通道等同在后端节点执行任意代码；只在排查时开启，用完立即停止；令牌仅存内存，节点重启自动失效。」

## 六、文案与细节规范

| 场景 | 现在的写法 | 建议写法 |
|---|---|---|
| 复制成功 | 已复制 | 已复制完整提示词（含密钥），请勿粘贴到公开群聊 |
| 项目锁定 | 下拉框直接 disabled | 锁图标 + tooltip「由当前项目决定，退出项目后可切换」 |
| 应用为空 | 请选择应用。项目下还没有应用时… | 该项目暂无应用。去「应用接入」创建 → |
| 凭证展示 | `Secret=明文` 混在提示词里 | `Secret: demo••••9f3c` + 显示 / 复制；复制时复制完整明文 |
| 提示词区 | `el-input textarea readonly` | 深色代码块 + 凭证遮蔽预览 + 顶部「复制时填入完整凭证」标记 + 变量 chips |
| 按钮尺寸 | mini / small 混排 | 统一 small（32px），主按钮默认（36px），遵循 `_apple-tokens.scss` |

视觉沿用项目已有的 Apple 风格 token：主色 `#0071e3`、表面 `#fff / #f5f5f7`、文字 `#1d1d1f / #6e6e73`、圆角 12px、阴影 `0 1px 2px rgba(0,0,0,.04)`，不要另起一套配色。

## 七、实施优先级

**P0（先做，安全与正确性）**
1. 凭证默认遮蔽、显示/复制分离；风险提示移到凭证旁
2. 取消默认选中第一个项目/应用，必须显式确认
3. 复制加 `execCommand` 兜底，失败文案给出可操作指引
4. 重新生成/停止令牌的确认文案写清后果

**P1（结构与状态）**
5. 三页统一为四步向导 + 右侧安全栏，命名与副标题调整（只改 `menu_name` 成本最低）
6. 接入清单状态持久化（localStorage）；运维页倒计时与连接记录
7. 控制页增加权限范围选择，生成页增加需求摘要表单

**P2（体验与工程）**
8. 试连、提示词变量说明、应用选项补充 appid 尾号/状态
9. 抽公共组件与场景配置，三页代码从三份收敛到一份
10. 补埋点：下载 SKILL、复制提示词、启动/停止通道，用于判断哪些页面真有人用

**验收清单**：复制的提示词是否与当前选中的项目/应用/权限一致；Secret 是否默认不可见且复制的是完整值；危险操作是否二次确认；锁项目时是否有解释；无项目/无应用/接口失败三种空态是否都有下一步动作；小屏（1280px）下右侧栏是否自然折行而不挤压主区。

## 八、原型使用说明

`docs/agent-ui-prototype.html` 是单文件、零依赖的可点击原型：左侧切换三个页面，页内四步可前进后退，凭证可遮蔽/显示，复制有 toast 兜底，运维页有真实倒计时、令牌重生成与停止确认弹窗。它只用于评审交互与视觉方向，不接入真实数据。
